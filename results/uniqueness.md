# M4: uniqueness curve (reference only, SYNTHETIC noise)

Generated by `scripts/uniqueness.py report` from `results/uniqueness_trials.csv`, `results/uniqueness_run.json`, `results/probe_noise.json` and `results/uniqueness_selfcheck.json`. Every number below is copied from those files by the script.

## What was done

- Excerpts are cut from the real one-second reference (Grid-India NERLDC PMU via Mendeley bvwh9d6227, 84,046,325 s from 2020-12-20 17:21:01 IST). No audio is used.
- Excerpt starts are drawn uniformly from all windows with at least 90% valid seconds, with seed 20261107. Lengths: 5, 10, 20, 40, 60 min. Missing seconds inside an excerpt are linearly interpolated.
- SYNTHETIC Gaussian noise is added to the 1-Hz trace. Two kinds:
  - `white`: independent each second.
  - `hann16`: the same normal draws smoothed by the probe extractor's 16 s Hann window and rescaled to the same standard deviation. Real extractor error is correlated over about 16 s, so this kind is the closer stand-in. For the same sigma it is harder for the matcher.
  - One normal vector per excerpt is shared by all noise conditions, so the levels differ only in scale.
- Noise levels: 0 (control), 10, 20, 40 and 60 mHz. They bracket the probe's equivalent noise (`results/probe_noise.json`, from `scripts/probe_noise.py`): median 38.6 mHz, range 8.5 to 58.2 mHz over 11 probe excerpts (median 38.0 mHz over the 5 raw-reference points).
  - How: the probe printed r at the true lock for several excerpts of one stream. If the trace is the grid frequency plus independent noise, r = s / sqrt(s^2 + sigma^2), where s is the reference's standard deviation over the matched window. So sigma = s * sqrt(1/r^2 - 1). s was measured on the series at each excerpt's matched window (file IV labels shifted by the 198 s IV-to-V label offset from `results/reference_build_stats.json`).
  - This sigma lumps together extractor noise, its smoothing and alignment error. It is one stream only.
  - Smoothing the reference like the extractor barely changed the probe's r: 20 min from second 120: 0.75 raw vs 0.751 smoothed; 40 min from second 120: 0.876 raw vs 0.876 smoothed. So most of sigma is extraction error, not the extractor's smoothing of the true wander.
- Scopes: the full span; +-90 days around the truth; +-1 day around the truth (clipped at the series ends).
- Search: the same normalised cross-correlation as `gunj.match.ncc_search` (90% valid windows, 0.003 Hz std floor, local peaks 60 s apart), batched so each reference block is transformed once for many queries. Block size 65,536 positions. Self-check (`results/uniqueness_selfcheck.json`): against `ncc_search` at the same block size, 36 of 36 searches gave the same top and runner-up with identical r (max difference 0.0e+00); against `ncc_search` at its default block size (2,097,152), 36 of 36 gave the same top and runner-up (max r difference 8.9e-16, FFT rounding).
- Hit: top-1 start within 30 s of the truth. Margin: r1 - r2, with r2 the best local peak at least 60 s from the top one. Wilson 95% intervals.
- Nesting: excerpt j is the same excerpt (and the same noise) in every scope. The cheap scopes get more excerpts than the full span.

Run size (from `results/uniqueness_run.json`):

- 1d: planned 2000 excerpts per length; done 5 min: 2000, 10 min: 2000, 20 min: 2000, 40 min: 2000, 60 min: 2000. Stop reason: planned N reached. Compute this run: 209.0 s.

## Limits

- The noise is synthetic and Gaussian. Real extraction error also has outliers, wrong-peak jumps and slow drifts, and it changes along a clip. The probe-derived level comes from one stream.
- The excerpt is the reference itself, so the true alignment is exact. Real clips also carry the time-label drift found in `results/time_axis_check.json` (up to a few minutes). That drift does not change uniqueness, but it does change whether a lock lands within 30 s of a metadata time.
- At the 4 file handovers 64 to 319 s of real time are missing without a gap in the mask (`results/reference_build_stats.json`, junctions). Excerpts that span a handover are kept; they still match themselves.
- Missing seconds inside an excerpt (up to 10%) are interpolated, which makes those seconds easier to match than real audio would.
